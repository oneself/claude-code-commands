# Task List Implementation

## Purpose

Guide the AI through implementing a task list generated by `/tasks`. Work
through one sub-task at a time, pausing for user approval between sub-tasks
so a junior-developer reader can follow what is happening.

## Process

Steps must be executed in numerical order. Complete each step before moving to
the next.

1. **Re-read the tasks file** from `$ARGUMENTS` to refresh the in-memory
   model of all tasks and their statuses.
2. **Pick the next sub-task:** Find the first sub-task that is not marked
   `[x]`. If you cannot tell which sub-task is next, stop and ask the user.
3. **Mark the sub-task in progress:** Change `[ ]` to `[~]` in the tasks
   file.
4. **Implement the sub-task:** Make the code changes required, and only
   those required. Do not start the next sub-task.
5. **Update the tasks file:**
   - Mark the finished sub-task `[x]`.
   - If all sub-tasks under a parent are now `[x]`, mark the parent `[x]`.
   - Add any newly discovered sub-tasks.
   - Keep the "Relevant Files" section accurate.
6. **Pause for approval:** Stop and wait for the user to say "yes" or "y"
   before starting the next sub-task. Then go back to step 1.

## Task List Maintenance

- Update the task list as you work: mark sub-tasks completed, add new
  sub-tasks as they emerge.
- Maintain the "Relevant Files" section: list every file created or
  modified with a one-line description of its purpose.

## AI Instructions

- Regularly update the task list file after finishing any significant work.
- Mark the in-progress sub-task `[~]` so the user can see where you are.
- Follow the completion protocol: mark sub-tasks `[x]`, then mark the parent
  `[x]` once all its sub-tasks are `[x]`.
- Add newly discovered sub-tasks under the right parent.
- Before starting work, check which sub-task is next.
- After implementing a sub-task, update the file and pause for approval.

## Code Style

- Focus on readability.
- Keep to 120 character row length.
- Trim trailing whitespace.
- Always end files with an empty line.

## Images

- Do NOT attempt to generate image assets (e.g. SVG, favicon.ico, etc.).
- If an image is needed, add a placeholder with the image path and a
  descriptive `alt` tag.
- Add the image to an image task file at
  `[YYYY-MM-DD]-[feature-name]-images.md` in `/tasks/`, where
  `[feature-name]` matches the base name of the input PRD file. Get the
  current date by running `date +%Y-%m-%d`.

### Images File Format

```markdown
## Images

- [ ] `[path-to-image1]` — Alt description of image 1
- [ ] `[path-to-image2]` — Alt description of image 2
```

### Updating Image Status

- If an image file exists at the path specified in the images task file,
  mark it complete with `[x]`.

## Important

- One sub-task at a time. Do NOT start the next sub-task until the user
  approves.
- NEVER commit or push code without explicit permission from the user.
